# TRANVIQ — повні кабінети компаній

Цей архів містить повний проєкт для заміни файлів у репозиторії O-O-TRANS.

## Встановлення

1. Розпакуйте архів. Відкрийте папку `O-O-TRANS-main`.
2. У GitHub відкрийте репозиторій O-O-TRANS → **Add file → Upload files**.
3. Завантажте файли з цієї папки в корінь репозиторію, замінивши однойменні. Обов’язково завантажте нові `tenancy.py` і `gps_providers.py`, а також оновлений `Dockerfile`.
4. Збережіть зміни через **Commit changes**. Дочекайтеся успішного deploy у Render.
5. У Render → Environment мають бути справжній `DATABASE_URL` PostgreSQL та постійний `SESSION_SECRET`. `SESSION_SECRET` має бути довгим випадковим секретом; його не потрібно надсилати в чат. За відсутності `SESSION_SECRET` вхід доведеться повторювати після перезапуску, але акаунти у PostgreSQL залишаться.
6. Залежність `psycopg[binary]` уже є в requirements.txt — додавати другий драйвер не потрібно.

Налаштування O&O TRANS (`ADMIN_USER`, `ADMIN_PASSWORD`, `NAVIREC_TOKEN`, `NAVIREC_ACCOUNT_ID`) залишаються її налаштуваннями. Нові компанії реєструються у програмі; їхні логіни й паролі не потрібно додавати в Render.

## Після встановлення

- Увійдіть через **Вхід компанії**. Для директора відкриваються головна, автомобілі, GPS, історія, паливо, тахограф, фінанси, документи, оплата доріг, брендинг, водії, паролі, стан системи та команда.
- **Підключення GPS** → оберіть Navirec або Wialon Hosting → введіть власні реквізити підключення → отримайте список машин → відмітьте потрібні → **Додати вибрані автомобілі**.
- Для ручних позицій оберіть **Без GPS / ручна позиція** і додайте автомобіль з координатами.
- У **Команда** створіть логіста або водія. Водію призначте автомобіль. Всі вони входять через **Вхід компанії** зі своїми логінами. Логін має бути унікальним у платформі.
- **Паролі** дозволяє змінити пароль або вимкнути доступ водію/логісту цієї компанії.
- Логіст не отримує фінанси й управління паролями; водій працює зі своїм автомобілем і документами.

## Збереження й розділення даних

Компанії, користувачі, автомобілі, налаштування GPS, маршрути, повідомлення й налаштування водіїв зберігаються у PostgreSQL через DATABASE_URL. Фінанси/Gmail і документи інших компаній використовують окремі схеми PostgreSQL без доступу до таблиць O&O TRANS. Брендинг уже має окремий ключ компанії. Дані GPS та кеші визначаються поточною компанією, у тому числі при одночасній роботі різних користувачів.

Створення схеми вимагає права CREATE у базі. Помилка бази не повинна відкривати дані іншої компанії.

Оригінальні таблиці й файли O&O TRANS не переміщуються. Постійність її старих файлових даних залежить від раніше налаштованого диска; ця зміна не переносить їх автоматично в нове сховище. Існуючі акаунти нових компаній у таблиці tranviq_company_store зберігаються. Старі акаунти, які були лише у /tmp до першого переходу на PostgreSQL, могли вже зникнути під час попереднього deploy.

## Межі GPS-інтеграцій

- **Navirec:** список машин, поточні позиції; історія, паливо та тахограф використовують наявні модулі за умови доступності відповідних даних/API.
- **Wialon Hosting:** список машин і останні позиції/швидкість. Історія повідомлень, датчики палива і тахограф Wialon ще не інтегровані. Такі поля залишаються невідомими; дані не підміняються.
- **Інший GPS:** можна вказати назву; саме підключення ще потребує адаптера API. Це не універсальне підключення до всіх GPS.
- Для фінансової пошти потрібні налаштовані загальні Google OAuth реквізити застосунку і окремий дозвіл кожної компанії на її Gmail.

## Перевірка на вашому Render

1. Увійдіть у O&O TRANS і перевірте три машини.
2. Увійдіть у тестову компанію й переконайтеся, що чужих машин, маршрутів, документів та фінансів немає.
3. Додайте тестовий автомобіль та маршрут, завантажте CMR.
4. Перезапустіть Render і перевірте, що акаунт і дані залишилися.
5. Підключіть реальний GPS і звірте машину та її позицію з кабінетом постачальника.

## Локальна перевірка

`PYTHONPATH=. python tests/test_companies.py`

Тести перевіряють сторінки, розділення двох компаній, призначення водія, доступ логіста, маршрути/повідомлення, документи, захист записів, імпорт GPS, одночасні запити та синтаксис згенерованого JavaScript (потрібен Node). Зовнішні GPS-запити та PostgreSQL-з’єднання в тестах замінені контрольованими відповідями. Потрібна окрема перевірка реальної PostgreSQL та реальних GPS-акаунтів після встановлення.
